# 디자인 스튜디오

사용자가 말로 "여기 좀 줄여 줘"를 반복하는 대신, **복제 앱에서 직접 만져 본 결과**를 Claude 가 실제 코드로 옮기고 더 다듬는 도구다.
스튜디오 본체는 별도 저장소(`design-studio`)에 있고, 앱마다 **앱 설정**(`studio.app.json`)과 **앱 규칙**(설정의 `context` 파일)을 둔다.

| 무엇 | 어디 |
|---|---|
| 스튜디오 본체 | `<스튜디오>/studio/` (서버·편집 도구·시안·AI·사진) |
| 앱 설정 | 앱별 `studio.app.json` (예: `<스튜디오>/adapters/daling/`). 띄우는 법·화면 폴더·요청 규칙·확인 명령 |
| 앱 규칙 | 설정의 `context` 파일. **반영하기 전에 반드시 읽는다** (테마 블록 위치, 번역, 빌드 등 앱마다 다른 것) |
| 저장본 | `<앱 저장소>/.design-studio/requests/<날짜-시각-제목>.md`(읽기용) + `.json`(정확한 값) |
| 시안 | `<앱 저장소>/.design-studio/proposals/<이름>/` — `web/`(Claude 가 고치는 복사본)·`base/`·`meta.json`·`before-apply/` |

`.design-studio/` 는 앱 저장소의 `.gitignore` 에 넣는다.

## A. 스튜디오 열기

```bash
cd <스튜디오 저장소>
python -m studio --app adapters/daling/studio.app.json --project <앱 저장소>            # 첫 모드(보통 demo)
python -m studio --app adapters/daling/studio.app.json --project <앱 저장소> --mode real
```

- 스튜디오가 앱 서버를 띄우고(설정의 `launch`) 그 앞에 프록시로 선다. 브라우저가 저절로 열린다(8796, 차 있으면 다음 빈 포트).
- 쓰기 요청(POST·PUT·PATCH·DELETE)은 설정의 `pass` 에 적은 것 말고는 '했다 치고' 답한다. 바깥 연결 차단·가짜 데이터는 앱 런처가 맡는다.
- 앱이 안 뜨면 `<앱 저장소>/.design-studio/app.log` 를 본다.

띄운 뒤 사용자에게 짧게 알려 줄 것:
- 아래 막대: **둘러보기(V)** 앱처럼 누르기 · **고르기(S)** 요소를 골라 오른쪽 패널에서 바꾸기 · **댓글(C)** 누르면 그 자리, 끌면 영역에 댓글
- 고른 요소를 끌면 자유롭게 옮기고, 오른쪽 아래 모서리로 크기를 바꾼다. ⠿ 는 순서 바꾸기. 두 번 누르면 글자 고치기.
- 단추를 고르면 **동작** 칸에서 누를 때 일어날 단계를 짜고 ▶ 시연. **AI 에게 알아보기**는 지금 동작을 코드에서 찾아 채운다.
- 왼쪽 아래 **✨ AI 추천**: "이건 어때요?" 카드가 뜨고 바뀔 곳이 반짝이며 시연된다. 담기 / 다음.
- 색은 **그라데이션 판**과 **스포이트**(화면 어디서든 색 따오기)로 고른다. **조합 A/B/…** 를 숫자 키로 비교.
- **저장해서 Claude에게** → **저장하고 시안 만들기**(D) 또는 **저장만**(B).

## B. 저장본 반영하기 (사용자가 "저장본 반영해 줘")

1. **앱 규칙 파일을 먼저 읽는다** (`studio.app.json` 의 `context`).
2. 저장본 고르기: 이름을 말했으면 그것, 아니면 `.design-studio/requests/` 바로 아래 가장 최근 것. `.md` 를 먼저, 애매하면 `.json`. `variants[chosen]` 이 반영할 조합이다.
3. 사용자가 본 화면을 직접 본다 (앱 저장소 폴더에서):
   ```bash
   python <스튜디오>/studio/snapshot.py <이름>
   ```
   `requests/shots/<이름>/<화면>-now.png`(지금)와 `-target.png`(요청한 모습)를 Read 로 열어 비교한다.
4. 소스로 옮기기 — **덮어쓰기 CSS 를 그대로 붙이지 않는다.** 원래 규칙을 찾아 고친다.

| 바뀐 것 | 어디를 고치나 |
|---|---|
| 색·모양 토큰 | 앱 CSS 의 테마 블록(위치는 앱 규칙). 저장본의 '테마' 열에 적힌 테마만 |
| 요소 모양 (`selector`·`prop`) | `target.rules` 에 적힌 규칙을 grep 해 그 선언을 고친다. `@media`·다른 테마의 짝 규칙도 본다 |
| 범위가 '이 요소만'(경로 선택자) | 경로를 그대로 쓰지 말고 뜻 있는 클래스·id 로 규칙을 단다. 필요하면 마크업에 클래스를 더한다 |
| 직접 고른 색(hex) | 가까운 토큰이 있으면 `var(--…)`. 새 색이면 토큰을 만들고 모든 테마에 값을 정한다 |
| 글자 | `from` 문구를 화면 파일에서 grep 해 바꾼다. 번역 파일이 있으면 앱 규칙대로 맞춘다 |
| 순서·위치(`move`, `translate`) | translate 를 그대로 쓰지 말고 margin·gap·정렬·배치·순서로 옮긴다 |
| 동작 흐름(`flow`) | '지금'(where) → '바라는 단계'. 그 처리기를 고친다. 확인 창·알림·화면 이동은 앱 규칙에 적힌 함수로 |
| AI 추천(`by: "ai"`) | 사용자가 시연을 보고 담은 것이라 사용자 요청과 똑같이 다룬다 |
| 너비·높이 px | 고정 px 보다 창 크기에 맞게 늘고 주는 쪽(`max-width`·grid 등) |

   댓글: `[고쳐 줘]`·`[아이디어]` 반영 · `[좋아요·유지]` 건드리지 않음 · `[질문]` 보고에 답 · `(해결됨)` 건너뜀.
   재량: `refine`(기본) 이면 hover·focus·다른 테마·좁은 창까지 맞추고 따로 적는다. `exact` 면 적힌 값만.
5. 확인: 앱 규칙의 확인 명령, `snapshot.py <이름> --tag after` 로 `-after.png` 를 `-target.png` 와 비교, 화면 오류 0.
6. 마무리: 저장본 `.md` 끝에 `## 반영 결과 (날짜)` 를 덧붙이고 `.json`·`.md` 를 `requests/applied/` 로 옮긴다(지우지 않는다). 빌드·설치·커밋은 앱 규칙과 사용자 말에 따른다.

## C. 새 앱에 붙이기 / 스튜디오 고치기

- 새 앱: `adapters/<앱>/studio.app.json` 을 만든다(`studio/config.py` 맨 위 설명). 최소 `webRoot` 와 `launch`(또는 `upstream`).
  화면 이름·테마·토큰을 알려 주려면 `client` 스크립트(`window.__STUDIO_APP__`, 예: `adapters/daling/studio.app.js`). 없으면 `:root` 의 CSS 변수를 찾아 쓴다.
  가짜 데이터·바깥 연결 차단이 필요하면 앱 런처를 만든다(예: `adapters/daling/run_demo.py`).
- 스튜디오를 고친 뒤: `node --check studio/assets/studio.js`, `python -m py_compile studio/*.py`, `python tests/run.py`(예제 앱으로 띄워 고르기·댓글·저장·다시 열기·보안 검사).

## D. 시안 모드 (스튜디오가 `claude -p` 로 너를 띄웠을 때)

사용자 흐름: **수정 요청 → 반영된 시안 → 최종 반영 여부 선택.**

- 프롬프트에 적힌 앱 규칙 파일을 먼저 읽는다.
- 고치는 곳은 프롬프트의 시안 폴더(`.design-studio/proposals/<이름>/web/`) 뿐이다. 진짜 화면 폴더는 읽기만 한다 — 권한이 `dontAsk` 라 허락 목록 밖은 묻지 않고 거절된다. 거절되면 우회하지 말고 마지막 답에 적는다.
- 반영 규칙은 B-4 와 같다. 다른 점: 저장본 옮기기·빌드·커밋은 하지 않는다. 사용자가 '이대로 반영' 을 누르면 스튜디오가 3-way 병합으로 넣는다(충돌이 하나라도 있으면 아무 파일도 쓰지 않는다).
- 확인: 프롬프트의 snapshot 명령으로 `*-proposal.png` 를 찍어 `*-target.png` 와 비교한다. 확인 명령은 프롬프트에 적힌 글자 그대로만 허락된다.
- '더 고쳐 줘' 는 같은 대화를 이어 새 요청을 준다. 그 요청의 선택자·글자는 **시안 기준**이다. 앞 회차를 되돌리지 말고 그 위에 고친다.
- 마지막 답은 시안 카드에 그대로 보인다. 한국어로 짧게: 댓글 번호별로 한 일 / 재량으로 더 한 것 / 못 했거나 안 한 것과 이유.

사용자가 Claude Code 에서 시안을 다룰 때 (스튜디오 밖):
- "시안 <이름> 반영해 줘" → `meta.json` 상태가 `ready` 인지 보고, 바뀐 파일마다 진짜 파일이 `base/` 와 같으면 복사, 다르면 `git merge-file` 로 합친다. 반영 전 파일은 `before-apply/` 에.
- "시안 <이름> 충돌 정리해 줘" → `applyReport.conflicts` 파일을 `base/`·시안·진짜 세 벌을 보고 손으로 합친 뒤 나머지 파일도 함께 옮긴다.
