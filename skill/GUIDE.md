# 디자인 스튜디오 안내서 (Claude 용)

사용자가 말로 "여기 좀 줄여 줘"를 반복하는 대신, **앱과 똑같이 생긴 연습용 복제 앱에서 직접 만져 본 결과**를 Claude가 실제 코드로 옮기고 다듬는 도구다.
도구 본체는 이 저장소(`<도구>`, 보통 `~/.claude/design-studio/tool`)에 있고, **앱마다 개인화 설정**을 앱 저장소의 `.claude/design-studio/`에 둔다.

| 무엇 | 어디 |
|---|---|
| 도구 명령 | `python <도구>/run_studio.py [open\|init\|doctor\|snapshot] …` |
| 개인화 설정 (커밋 대상) | `<앱>/.claude/design-studio/` — `studio.app.json` · `studio.app.js` · `context.md` · (필요하면) `run_demo.py`·가짜 데이터 |
| 저장본·시안·로그 (git 제외) | `<앱>/.design-studio/` — `requests/` · `proposals/` · `app.log` · `doctor.json` |
| 설정 칸 설명 | `<도구>/studio/config.py` 맨 위 |
| 런처 틀 | `<도구>/templates/launcher_python.py` |

파이썬은 앱 저장소의 가상환경(`.venv`)이 있으면 그것을 쓴다. 표준 라이브러리만 쓰며, 사진·점검에는 Playwright(Chromium)가 필요하다. 없으면 `pip install playwright` 하고 `playwright install chromium`을 하자고 사용자에게 묻는다.

## 0. 지킬 것

- 스튜디오는 **앱에 실제로는 아무것도 하지 않는다**. 쓰기 요청은 가짜 답, 연습 모드는 지어낸 데이터와 바깥 연결 차단. 개인화할 때 이 약속이 깨지지 않게 한다.
- 비밀번호·API 키를 설정·가짜 데이터·코드에 적지 않는다. 화면이 '연결됨'으로 보여야 하면 런처가 실행마다 무작위 값을 메모리에만 넣는다.
- 가짜 데이터에 실제 사람 이름·메일·학번·주소를 넣지 않는다.
- 앱 저장소의 규칙(`CLAUDE.md` 등)이 이 안내서보다 우선한다. 특히 커밋·빌드·설치는 그 규칙과 사용자 말에 따른다.
- 내가 띄우지 않은 프로세스는 끄지 않는다. 포트가 차 있으면 다음 포트로 뜬다.

## 1. 개인화 (처음 한 번, 앱 구조가 바뀌었을 때)

### 1-1. 초안 만들기
```
python <도구>/run_studio.py init --project <앱>
```
`<앱>/.claude/design-studio/`에 초안과 `analysis.md`(찾은 것·불확실한 것·확인할 것)가 생긴다. 이미 설정이 있으면 `analysis.md`만 새로 쓴다(덮어쓰기는 `--force`, 예전 것은 `.bak`).

### 1-2. 앱을 읽고 다듬기
`analysis.md`의 '확인할 것'을 하나씩 처리한다. 먼저 앱의 `CLAUDE.md`·기능 문서·화면 파일·서버 입구를 읽는다.

| 파일 | 다듬을 것 |
|---|---|
| `studio.app.json` | **띄우기**: `launch`(포트 자리 `{port}`) / 이미 떠 있는 `upstream` / 서버 없는 화면은 `"serve": "static"`. **모드**: 사용자 데이터를 읽는 앱이면 `modes.demo`(가짜 데이터, 첫 모드) + `modes.real`(내 데이터, 쓰기 막음). **요청 규칙**: 바깥 서버에서 받아 오는 GET은 `mock`에 그럴듯한 빈 답, 임시 데이터 안에서만 끝나는 쓰기(설정·정렬·선택 저장)만 `pass`, 원본 파일 내려받기 같은 것은 `deny`. **확인 명령** `checks`(정확한 글자로만 허락되니 짧고 안전한 것). 번들러 앱은 `"proposals": false` |
| `run_demo.py` (직접 만든 서버·사용자 데이터·바깥 연결이 있는 파이썬 앱) | 틀의 '고칠 곳' 세 군데: 데이터 폴더 환경 변수, 지어낸 데이터, 서버 띄우기. 네트워크 차단·임시 폴더 정리는 틀이 한다. Node 서버면 같은 일을 하는 작은 런처를 만든다(바깥 요청을 막는 `--require` 훅 등) |
| `studio.app.js` | 화면 이름표(사람 말), 테마 이름표(한국어), **화면 이동은 앱의 함수**로(`switchView` 같은 것이 있으면 단추 누르기 대신), 테마 바꾸기도 앱 함수로(로고·차트까지 따라 바뀌게, 저장은 하지 않게), `toast`·`dialog`에 앱의 알림·확인 창, `ready()`는 첫 화면이 다 그려졌음을 알 수 있는 표시를 기다리게. 토큰 묶음 이름·순서도 다듬는다 |
| `context.md` | '채울 것'을 채운다. **60줄 안팎**으로 짧게: 디자인 말투(색감·글꼴·모서리·문구), 테마 블록 위치, 화면 코드 규칙(숨기기·다시 그리기·알림 함수), 번역 파일, 반영 뒤 할 일(빌드·설치). AI 추천과 시안 프롬프트에 그대로 들어간다 |

### 1-3. 점검
```
python <도구>/run_studio.py doctor --project <앱> --screenshot
```
**실패 0**이 될 때까지 다듬는다. '주의'는 이유가 있으면 둔다(예: 글꼴 CDN 요청). 사진(`.design-studio/doctor.png`)을 Read로 열어 앱이 제대로 그려졌는지 눈으로 본다. 모드가 여럿이면 `--mode real`도 한 번 돌린다.

### 1-4. 마무리
- 앱의 `.gitignore`에 `.design-studio/`를 넣는다. `.claude/`가 통째로 무시되는 저장소면 `!.claude/design-studio/` 예외를 더한다.
- 앱에 `CLAUDE.md`가 있으면 명령 절에 한 줄을 더한다: 스튜디오 여는 법과 개인화 폴더 위치.
- 사용자에게 짧게 보고한다:
  - 무엇을 개인화했는지
  - 연습 모드가 무엇을 막는지
  - 여는 명령
  - doctor 결과(통과·주의·실패 수)
- 커밋은 앱 규칙대로 한다.

## 2. 열기

```
python <도구>/run_studio.py --project <앱>                # 첫 모드 (보통 demo)
python <도구>/run_studio.py --project <앱> --mode real    # 내 데이터 (쓰기 막음)
```
브라우저가 저절로 열린다(8796, 차 있으면 다음 포트). 앱이 안 뜨면 `<앱>/.design-studio/app.log`를 본다.
클라우드 세션처럼 사용자가 이 컴퓨터의 브라우저를 못 보면, 사용자 PC에서 열 명령을 알려 준다. 도구 받기와 위 명령이면 된다.
화면을 보여 줄 때는 `doctor --screenshot`이나 `snapshot`을 쓴다.

사용자에게 알려 줄 것 (짧게):
- **막대**:
  - **둘러보기(V)** 앱처럼 누르기
  - **고르기(S)** 요소를 골라 오른쪽 패널에서 바꾸기
  - **댓글(C)** 누르면 그 자리, 끌면 영역에 댓글
- **고른 요소 다루기**:
  - 끌면 옮긴다(Shift: 한 방향).
  - 오른쪽 아래 모서리로 크기를 바꾼다.
  - ⠿ 로 순서를 바꾼다.
  - 두 번 누르면 글자를 고친다. ↑ 는 바깥 상자로 간다.
- **단추 동작**: 단추를 고르면 **동작** 칸에서 누를 때 일어날 단계를 짜고 ▶ 시연한다. **AI 에게 알아보기**는 지금 동작을 코드에서 찾는다.
- **✨ AI 추천**: "이건 어때요?" 카드가 바뀔 곳을 반짝이며 시연한다. 담기 / 다음.
- **색과 조합**: 색은 **그라데이션 판**과 **스포이트**(화면 어디서든)로 고른다. **조합 A/B**를 숫자 키로 비교한다.
- **저장해서 Claude에게** → **저장하고 시안 만들기**(4) 또는 **저장만**(3).

## 3. 저장본 반영

1. `context.md`(앱 규칙)를 먼저 읽는다.
2. 저장본을 고른다.
   - 이름을 말했으면 그것을 쓴다.
   - 아니면 `<앱>/.design-studio/requests/` 바로 아래에서 가장 최근 것을 쓴다.
   - `.md`를 먼저 읽고, 애매하면 `.json`을 본다. 반영할 조합은 `variants[chosen]`이다.
3. 사용자가 본 화면을 본다. 앱 저장소 폴더에서:
   ```
   python <도구>/run_studio.py snapshot <이름>
   ```
   `requests/shots/<이름>/<화면>-now.png`(지금)와 `-target.png`(요청한 모습)를 Read로 연다.
4. 소스로 옮긴다. **덮어쓰기 CSS를 그대로 붙이지 않는다.**

| 바뀐 것 | 어디를 고치나 |
|---|---|
| 색·모양 토큰 | 앱 CSS의 테마 블록(위치는 앱 규칙). 저장본의 '테마' 열에 적힌 테마만 |
| 요소 모양(`selector`·`prop`) | `target.rules`에 적힌 규칙을 grep해 그 선언을 고친다. `@media`·다른 테마의 짝 규칙도 본다 |
| '이 요소만'(경로 선택자) | 경로를 그대로 쓰지 말고 뜻 있는 클래스·id로 규칙을 단다. 필요하면 마크업에 클래스를 더한다 |
| 직접 고른 색(hex) | 가까운 토큰이 있으면 `var(--…)`를 쓴다. 새 색이면 토큰을 만들고 모든 테마에 값을 정한다 |
| 글자 | `from` 문구를 grep해 바꾼다. 번역 파일은 앱 규칙대로 |
| 순서·위치(`move`, `translate`) | translate를 그대로 쓰지 말고 margin·gap·정렬·배치·순서로 옮긴다 |
| 동작 흐름(`flow`) | '지금'(where) → '바라는 단계'. 그 처리기를 고친다. 확인 창·알림·화면 이동은 앱 규칙의 함수로 |
| AI 추천(`by: "ai"`) | 사용자가 시연을 보고 담은 것이다. 사용자 요청과 똑같이 다룬다 |
| 너비·높이 px | 창 크기에 맞게 늘고 주는 쪽(`max-width`, grid 등)으로 |

댓글:
- `[고쳐 줘]`·`[아이디어]` → 반영한다.
- `[좋아요·유지]` → 건드리지 않는다.
- `[질문]` → 보고에서 답한다.
- `(해결됨)` → 건너뛴다.

재량:
- `refine`(기본) → hover·focus·다른 테마·좁은 창까지 맞추고, 더 한 것을 따로 적는다.
- `exact` → 적힌 값만 옮긴다.

5. 확인한다.
   - 앱의 확인 명령을 돌린다.
   - `snapshot <이름> --tag after`로 `-after.png`를 찍어 `-target.png`와 비교한다.
   - 화면 오류가 0이어야 한다.
6. 마무리한다.
   - 저장본 `.md` 끝에 `## 반영 결과 (날짜)`를 덧붙인다.
   - `.json`·`.md`를 `requests/applied/`로 옮긴다(지우지 않는다).
   - 빌드·설치·커밋은 앱 규칙과 사용자 말에 따른다.

## 4. 시안 모드 (스튜디오가 `claude -p`로 너를 띄웠을 때)

사용자 흐름: **수정 요청 → 반영된 시안 → 최종 반영 여부 선택.**

- 프롬프트에 적힌 앱 규칙 파일을 먼저 읽는다.
- 고치는 곳은 시안 폴더(`.design-studio/proposals/<이름>/web/`)뿐이다.
  - 진짜 화면 폴더는 읽기만 한다.
  - 권한이 `dontAsk`라 허락 목록 밖은 묻지 않고 거절된다. 거절되면 우회하지 말고 마지막 답에 적는다.
- 반영 규칙은 3-4와 같다. 다른 점이 있다.
  - 저장본 옮기기·빌드·커밋은 하지 않는다.
  - 사용자가 '이대로 반영'을 누르면 스튜디오가 3-way 병합으로 넣는다. 충돌이 하나라도 있으면 아무 파일도 쓰지 않는다.
- 확인:
  - 프롬프트의 snapshot 명령으로 `*-proposal.png`를 찍어 `*-target.png`와 비교한다.
  - 확인 명령은 프롬프트에 적힌 글자 그대로만 허락된다.
- '더 고쳐 줘'는 같은 대화를 이어 새 요청을 준다.
  - 그 요청의 선택자·글자는 **시안 기준**이다.
  - 앞 회차를 되돌리지 말고 그 위에 고친다.
- 마지막 답은 시안 카드에 그대로 보인다. 한국어로 짧게 쓴다:
  - 댓글 번호별로 한 일
  - 재량으로 더 한 것
  - 못 했거나 안 한 것과 이유

스튜디오 밖에서 사용자가 시안을 다룰 때:
- "시안 <이름> 반영해 줘"
  1. `meta.json` 상태가 `ready`인지 본다.
  2. 바뀐 파일마다 진짜 파일이 `base/`와 같으면 복사하고, 다르면 `git merge-file`로 합친다.
  3. 반영 전 파일은 `before-apply/`에 둔다.
- "시안 <이름> 충돌 정리해 줘"
  1. `applyReport.conflicts`의 파일을 `base/`·시안·진짜 세 벌을 보고 손으로 합친다.
  2. 나머지 파일도 함께 옮긴다.

## 5. 업데이트

- **도구**: `git -C <도구> pull --ff-only`.
  - 개인화 설정의 `studioVersion`보다 도구가 오래되면 스튜디오가 알려 준다.
  - 새 판의 `CHANGELOG`나 커밋에서 설정 칸이 바뀌었으면 개인화를 고친다.
- **앱이 바뀌었을 때** (새 화면·새 테마·새 토큰·서버 구조 변경):
  1. `init --project <앱>`으로 `analysis.md`만 새로 쓴다.
  2. 지금 설정과 비교해 빠진 것을 더한다.
  3. `doctor`로 확인한다.

## 6. 도구 자체를 고칠 때 (이 저장소에 기여)

- 앱 이름이 들어간 코드를 도구에 넣지 않는다. 앱마다 다른 것은 설정·client·런처로 뺀다.
- 고친 뒤 `node --check studio/assets/studio.js`, `python -m py_compile studio/*.py`, `python tests/run.py`를 돌린다.
- 보안 경계(스튜디오 API CSRF·호스트 검사, 시안 Claude 권한, 사진 찍기 브라우저 차단)를 넓히는 변경은 이유를 커밋에 적는다.
